Revizto ACC

Revizto and ACC use different status/type vocabularies — configure how they map for each project. Unconfigured statuses/types fall back to built-in defaults. Uses the project selected above.

The 4 common Revizto statuses — Open, In progress, Solved, Closed — always auto-map to their ACC equivalent (grey rows above, nothing to do), in any workflow. 1) Every other custom status is grouped below by the specific workflow it belongs to — a project can have multiple workflows, and two workflows can each define a status with the same name that needs a different ACC mapping, so each workflow's custom statuses are configured independently. 2) A workflow's group is shown as required once any issue is currently using that workflow — every one of its statuses needs a mapping, since the issue could reach any of them. Only if unmapped does it default to ACC "Draft" as a safeguard — and flags a warning (see Mapping warnings tab) plus a sync error on the Issues page until you map it. 3) A workflow not yet used by any issue is also listed, marked "Optional mapping" — set it up ahead of time if you like, but it's never flagged as a warning until a real issue starts using it. 4) The "ACC Secondary Status" column is optional and only matters when two statuses in the same workflow share the same ACC Primary Status — set it to a specific option from an ACC list field you create, requires an ACC admin to create it first (the column shows "Not available" until one exists for that workflow). You can create one shared field named exactly "Revizto Status", or — recommended once you have several workflows, so each dropdown only shows that workflow's own statuses instead of one long combined list — a separate field per workflow named "Revizto Status - <workflow name>" (e.g. "Revizto Status - Pre Pour Checklist"), matched by that exact suffix. If a status's name exactly matches one of its field's options, it auto-maps with nothing to configure (greyed out, marked "auto" — same idea as the standard statuses above). When an ACC user changes that field directly, the app updates Revizto to that exact status. If the primary ACC status alone is ambiguous (matches more than one status in the workflow) and this field isn't set to a value that resolves it, the app can't tell which one was meant — it defaults ACC's status back to "Draft" and flags a warning rather than guessing, and leaves Revizto's status untouched.

Every Revizto stamp currently in use is listed below. 1) Your mapping below is used if you've set one. 2) Otherwise it falls back to this project's Default ACC issue type (set per project in the list below — "General" is a good choice). 3) If that's not set either, a title-keyword guess, then an auto-detected "General" subtype, then whatever's available — this can never fail to sync, but an unmapped stamp is highlighted red and flags a warning (see Mapping warnings tab) plus a sync error on the Issues page until you map it.

In-use statuses and stamps with no configured mapping yet (see Status/Issue type mapping above) — the same information also shows as a sync error on the Issues page until resolved.

Off by default. When enabled, any signed-in user (not just admins) can manually unlink an issue from the Issues page — this only removes the link this app tracks between the Revizto and ACC issue, it never deletes the issue itself in either system. Mainly useful for recovering from a broken link (e.g. the ACC issue was deleted directly in ACC) — a broken link to a deleted ACC issue also now self-heals automatically on its own during the next push/resync, so this toggle is for anything that needs a manual fix.
