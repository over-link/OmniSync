Field mapping

Revizto and ACC use different status/type vocabularies — configure how they map for each project. Unconfigured statuses/types fall back to built-in defaults. Uses the project selected above.

Status mapping (Revizto → ACC)

Every Revizto status belongs to a category — "To do", "Tracking", or "Completed". 1) "To do"/"Completed" always auto-map to ACC (grey rows below, nothing to do). 2) For "Tracking" statuses, your mapping below is used if you've set one. 3) Only if unmapped does it default to ACC "Draft" as a safeguard — and flags a warning here plus a sync error on the Issues page until you map it. Every Tracking status currently in use is listed (not just synced ones), so you can configure a project fully before syncing starts.

Status mapping (ACC → Revizto)

4 unambiguous ACC statuses always auto-map to Revizto (grey rows below, nothing to do). 1) For the rest, your mapping below is used if you've set one, whenever an issue's status changes in ACC — choices are limited to Revizto's 4 common statuses (Open/In progress/Solved/Closed) to keep this simple. 2) Only if unmapped does it fall back to a built-in guess (e.g. ACC "Pending" → Revizto "Open") — highlighted red, and flags a warning here, since that guess isn't always what you actually want.

Issue type mapping

Every Revizto stamp currently in use is listed below. 1) Your mapping below is used if you've set one. 2) Otherwise it falls back to this project's Default ACC issue type (set per project in the list below — "General" is a good choice). 3) If that's not set either, a title-keyword guess, then an auto-detected "General" subtype, then whatever's available — this can never fail to sync, but an unmapped stamp is highlighted red and flags a warning here plus a sync error on the Issues page until you map it.
