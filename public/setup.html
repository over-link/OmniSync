Revizto and ACC use different status/type vocabularies — configure how they map for each project. Unconfigured statuses/types fall back to built-in defaults. Uses the project selected above.

The 4 common Revizto statuses — Open, In progress, Solved, Closed — always auto-map to their ACC equivalent (grey rows below, nothing to do). 1) Every other custom status belonging to a workflow currently governing an issue is listed below as required — as soon as any issue starts using that workflow, all of its statuses need a mapping, since the issue could reach any of them. 2) Only if unmapped does it default to ACC "Draft" as a safeguard — and flags a warning (see Mapping warnings tab) plus a sync error on the Issues page until you map it. 3) Custom statuses whose workflow isn't in use by any issue yet are also listed, marked "Optional mapping" — set one ahead of time if you like, but they're never flagged as a warning until a real issue actually starts using that workflow. (ACC → Revizto status has no admin mapping — it always auto-maps the same 4 statuses and falls back to a built-in guess for the rest.)

Every Revizto stamp currently in use is listed below. 1) Your mapping below is used if you've set one. 2) Otherwise it falls back to this project's Default ACC issue type (set per project in the list below — "General" is a good choice). 3) If that's not set either, a title-keyword guess, then an auto-detected "General" subtype, then whatever's available — this can never fail to sync, but an unmapped stamp is highlighted red and flags a warning (see Mapping warnings tab) plus a sync error on the Issues page until you map it.

In-use statuses and stamps with no configured mapping yet (see Status/Issue type mapping above) — the same information also shows as a sync error on the Issues page until resolved.

Optional, off by default. When enabled, any currently-unlinked issue matching every filter below gets automatically linked & pushed — on the same 2-minute cycle as the existing auto-resync, so this also sweeps up any matching backlog the first time it runs, not just new issues going forward. Same fields and combination rules as the Issues page filters: multiple values within one filter are OR'd together, different filters are AND'd together. Uses the project selected above. Leaving every filter empty means nothing gets auto-linked, even with the toggle on — there's no "auto-link everything" switch here by design.
